# Phishing URL Checker Brand System

The repository uses a **Threat Lens / URL Forensics** visual identity.

The product is not presented as a generic shield, antivirus product or live threat-intelligence service. Its visual language focuses on one thing the software genuinely does: dissecting the text structure of a URL and exposing explainable signals.

## Core idea

**Inspect the structure. Explain the evidence. Keep the URL local.**

## Logo

The mark uses a forensic lens passing over a URL-like line. A red evidence block inside the inspected line represents a suspicious structural signal. The amber handle differentiates the mark from generic security shields and padlocks.

## Hero concept

The hero decomposes a documentation-safe example into:

- scheme;
- user-info;
- host;
- path;
- query;

then routes those pieces into explainable findings and a risk bar.

## Visual rules

1. Prefer forensic/instrumentation visuals over cyber-neon hacker imagery.
2. Do not use a shield as the primary project symbol.
3. Amber represents caution and investigation.
4. Red represents stronger structural findings, not a declaration that a URL is malicious.
5. Mint represents the offline/local privacy boundary.
6. Never show page screenshots or reputation results the program does not produce.
7. Keep example URLs documentation-safe.

## Repository presentation rules

- State clearly that analysis is lexical/structural.
- Keep “no network request” prominent.
- Never equate a score with a verdict.
- Prefer stable finding codes when discussing automation.
- Keep Arabic and English detailed guides separate.
- Future online reputation providers, if ever added, must be described as future/opt-in until implemented.
